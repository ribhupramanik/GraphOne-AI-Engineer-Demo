# Reproducible six-tab submission export

`src.cli export` deliberately writes the **complete historical database** into `output/csv`. It does not filter expired jobs/news or remove generic Hugging Face README boilerplate. Those are handled by `scripts/prepare_submission.py`.

After a fresh signals run:

```bash
python -m src.cli signals --enrich-llm --llm-limit 10
python -m src.cli export
python scripts/prepare_submission.py
python -m pytest -q
```

`output/submission` now contains all six CSVs, plus `submission_manifest.json` with the exact UTC creation time, counts, freshness exclusions, and number of generic placeholders cleared. The six source CSVs are never edited. Job/news filtering uses a strict rolling 24-hour window; rerun **immediately before** submission.

To upload the CSVs into a Google Sheet manually, use **File → Import → Upload → Insert new sheet(s)**, with tab names: Startups, Products, Research Papers, Jobs, News, Entity Mapping Log. Set "Anyone with the link → Viewer" and verify access in a private window.

To publish with the existing Google OAuth script instead:

```bash
pip install -r requirements-google.txt
python scripts/publish_to_sheets.py --csv-dir output/submission --credentials credentials.json --public
```

The OAuth flow requires your own Google Cloud Desktop OAuth client credentials file and enabled Google Sheets and Drive APIs. Do **not** commit credentials, tokens, `.env`, `output/`, or runtime logs.

The downloaded reviewed `.xlsx` is a static snapshot, not a file generated by `src.cli export`. The reproducible deliverable is the six CSVs published to Google Sheets using the steps above. Repeatedly refreshing the sheet requires rerunning this script as record freshness changes.
